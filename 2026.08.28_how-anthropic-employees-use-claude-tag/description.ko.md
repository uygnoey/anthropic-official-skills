# Anthropic 직원들은 Claude Tag을 어떻게 쓰는가

## 이 글이 뭔가요

Slack 같은 채팅 도구 안에서 동작하는 Claude Tag을 Anthropic 팀들이 실제로 활용한 세 가지 사례.
프로덕트 마케터는 긴 스레드를 검토 가능한 원페이저로 바꾸고, 프로덕트 전략 담당자는 여러 채널에 흩어진
기능 요청을 통합하며, 프로덕트 카운슬은 법무 검토 전에 마케팅 자산을 걸러내는 리뷰 채널을 운영한다.
각 사례마다 프롬프트의 형태, 걸린 시간, 사람이 직접 붙든 부분이 함께 제시된다.

## 언제 유용한가요

- 결정 사항이나 스펙이 스레드 안에 묻혀 있는데 누군가 그것을 문서로 필요로 할 때.
- 같은 요청이 여러 채널에서 반복 등장하는데 통합된 목록이 아무 데도 없을 때.
- 전문가 검토 대기열이 병목인데, 정작 대부분의 항목은 문제가 없을 때.
- 채팅 안의 에이전트에게 무엇을 어떤 접근 권한으로 맡길지 정할 때.

## 핵심 포인트

- **스레드에서 태그하면 대화 맥락을 그대로 활용한다.** 대화를 따라가고, 상시 지침을 참고하며, 언제
  개입할지 스스로 판단한다.
- **스레드 → 문서: 45분.** 15개가 넘는 메시지의 스레드가 검토 가능한 원페이저가 되었다. Claude는 2분
  만에 두 페이지 초안(기능 설명, 비즈니스 근거, 구현 세부사항, 부록)을 냈고, 이후 네 번의 검증이
  이어졌다.
- **검증은 사람의 몫이다.** Claude가 검증된 주장과 프로덕트 리드 승인이 필요한 주장을 구분했고,
  마케터가 공식 자료를 제공하자 Claude가 다시 썼다.
- **통합: 약 26분.** 채널 전반에 걸친 약 20가지 검색 변형과 중복 제거를 통해, 요청자 핸들·팀·계정명·
  원본 링크가 붙은 약 24개 계정 목록이 나왔다.
- **주간 버전: 50분.** 약 120건의 원시 보고가 제품 영역별로 정리된 미해결 23건과 해결 14건이 되었다.
  수작업 추정치는 풀타임 일주일.
- **통합 작업의 프롬프트 구조:** 검색 대상, 무엇을 일치로 볼지, 예시를 포함한 출력 형식.
- **리뷰 채널: 하루에서 자산당 30분으로.** Claude는 근거 없는 주장을 찾아내고, 사실 진술을 검증하며,
  구체적 수정 지시와 함께 문제를 표시하고, 요청자와 직접 소통한다. 한 뉴스레터에서는 세 건을 표시하고
  그중 하나는 스스로 해결했다.
- **스스로 개선되는 지침.** 한 번의 수정이 상시 지침이 되었고, 금요일 루틴으로 Claude가 그 주의
  피드백을 바탕으로 지침 수정안을 제안한다(승인은 사람).
- **접근 권한은 의도적으로 좁게** 부여된 채널과 문서로 제한되며, 작업에 필요한 권한이 없으면 사용자에게
  알린다.
- **제공 범위:** Anthropic의 자사 서비스로 Team 및 Enterprise 플랜에 제공되며, 설정은
  claude.ai/admin-settings/claude-tag. 현재 퍼블릭 베타.
