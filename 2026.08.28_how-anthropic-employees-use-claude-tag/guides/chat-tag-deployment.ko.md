# 팀 전반에 Claude Tag 도입하기

Claude Tag은 Slack 같은 채팅 도구 안으로 Claude를 불러온다. 스레드에서 태그하면 대화의 맥락을 그대로
활용해 작업을 처리한다. 대화를 따라가고, 미리 정해둔 상시 지침을 참고하며, 언제 끼어들지 스스로
판단한다.

이 가이드는 Anthropic 팀들이 이 기능을 어떻게 활용했는지, 각 도입에 무엇이 필요했는지, 롤아웃 전에
무엇을 준비해야 하는지를 다룬다.

## 무엇이 달라지는가

지식 노동의 병목은 글쓰기가 아니다. 입력물 — 긴 스레드, 여러 채널에 흩어진 보고, 자산과 그것을
뒷받침하는 근거 — 을 먼저 찾아내야 한다는 점이다. Claude Tag은 그 입력물이 이미 있는 자리에 놓인다.

아래 모든 사례에서 역할 분담은 동일하다. Claude는 정보의 종합과 처리를 맡고, 사람은 판단과 검증,
의사결정을 맡는다.

## 세 가지 도입 패턴

### 스레드를 문서로

한 프로덕트 마케터는 15개가 넘는 메시지가 쌓인 스레드를 45분 만에 검토 가능한 원페이저로 만들었다.
프롬프트는 스레드를 가리키고 만들 산출물을 지목하는 한 문장이었다. Claude는 2분 만에 두 페이지 초안을
내놓았다 — 기능 설명, 비즈니스 근거, 구현 세부사항, 부록.

나머지 45분은 검증이었다. Claude가 스스로 사실관계를 점검해 검증된 주장과 프로덕트 리드의 승인이 필요한
주장을 구분했고, 마케터가 공식 자료를 제공하자 Claude가 해당 부분을 다시 썼다. 공유하기까지 총 네 번의
버전을 거쳤다.

**준비할 것:** 초안 작성이 아니라 검증 루프. 사람의 시간은 여기에 들어간다.

### 흩어진 언급을 하나의 목록으로

프로덕트 전략 팀원은 여러 채널에 흩어진 기능 요청을 통합했다. 어떤 영업 담당자가 어떤 고객을 대신해
요청했는지까지 포함해서다. 약 26분, 약 20가지 검색 변형, 중복 제거를 거쳐 요청자 Slack 핸들, 팀,
계정명, 원본 링크가 붙은 약 24개 계정 목록이 나왔다.

이를 주간 다이제스트로 넓히면, 엔터프라이즈 고객이 제기한 모든 제품 문제 약 120건의 원시 보고가 50분
만에 제품 영역별로 정리된 미해결 23건과 해결 14건이 되었다. 각 항목에는 요약과 원본 스레드 링크가
붙었다. 수작업 추정치는 풀타임 일주일이었다.

**준비할 것:** 검색 대상, 무엇을 일치로 볼지, 예시 행을 포함한 출력 형식을 명시하는 프롬프트. 중복
제거를 가능하게 하는 것은 일치 기준이다.

### 전문가 앞단에 두는 리뷰 채널

한 프로덕트 카운슬은 법무 검토에 앞서 Claude가 마케팅 자산을 검토하는 전용 Slack 채널을 만들었다.
자산당 처리 시간이 하루 이상에서 약 30분으로 줄었다.

설정: 구체적인 규칙과 지침, 그리고 회사 Slack, 사내 지식 인덱스, 공개 웹에 대한 접근 권한. Claude는
근거 없는 마케팅 주장을 찾아내고, 사실 진술을 검증하며, 문제를 구체적인 수정 지시와 함께 표시하고,
요청자와 직접 소통해 해결한다. 어떤 뉴스레터에서는 세 건을 표시했고, 그중 하나는 사내 문서에서 근거를
찾아 스스로 해결했다.

**준비할 것:** 스스로 개선되는 지침 세트. 한 번의 피드백이 상시 지침("가능하면 표시한 주장을 실시간으로
검증하라")이 되었고, 금요일 루틴으로 Claude가 그 주의 피드백을 검토해 지침 수정안을 제안한다 — 승인은
사람이 한다.

## 접근 권한과 거버넌스

- 접근은 **의도적으로 좁게** 설정된다. Claude Tag은 부여받은 채널과 문서에만 접근한다.
- 작업에 필요한 접근 권한이 없으면 조용히 넘어가지 않고 **사용자에게 알린다**.
- 워크플로 단위로 부여하라. 리뷰 채널에는 지식 인덱스가 필요하지만, 스레드 요약에는 대개 필요 없다.

## 제공 범위와 설정

- **Team 및 Enterprise** 플랜에서 Anthropic의 자사 서비스로 제공된다.
- 관리자 설정 위치는 **claude.ai/admin-settings/claude-tag**.
- 현재 **퍼블릭 베타**.

## 효과적인 롤아웃 순서

1. 입력물이 이미 채팅에 있고 비용이 "찾는 일"에 있는 **반복 작업 하나를 고른다**.
2. 먼저 스레드에서 태그해 **애드혹으로 실행**하고, 검증 루프를 명시적으로 유지한다.
3. 프롬프트가 안정되면 상시 지침을 둔 **채널로 승격**한다.
4. **그 워크플로에 필요한 접근 권한만 부여**하고, 알림으로 드러난 공백이 정당화될 때 넓힌다.
5. 수정 사항이 반복되지 않고 축적되도록 **지침 검토를 정례화**한다.
