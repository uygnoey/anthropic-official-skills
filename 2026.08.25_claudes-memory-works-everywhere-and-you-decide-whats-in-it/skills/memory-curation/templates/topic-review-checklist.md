# Topic file review checklist

One pass over a single file in **Settings > Memory > Topics**. Repeat per file; the files are
short, so a full review is usually a short session rather than a project.

## 1. Read it as written

- [ ] Open the file and read it end to end.
- [ ] Does the topic still describe something current, or has the situation moved on?

## 2. Check the facts that get reused

- [ ] Names of people, teams, and the company — is anything using an old name?
- [ ] Dates and deadlines — is anything superseded? (A deadline that moved to September should
      say September.)
- [ ] Definitions the team relies on, such as how a metric is calculated.
- [ ] Preferences attached to a person, such as how a recipient likes updates written.

## 3. Decide the action

- [ ] **Edit** — part of the file is wrong or stale, but the topic is still relevant. Fix it in
      place; the correction applies to every later conversation in chat and Cowork.
- [ ] **Delete** — the whole topic is obsolete.
- [ ] **Leave** — accurate and still useful.

## 4. Check the sensitivity boundary

- [ ] Does the file contain a personal or sensitive subject (health, race, ethnicity, religious
      beliefs, politics, gender identity, or similar)? If it does, it was saved because
      "include sensitive topics in memory" is on — confirm that is still the intent.
- [ ] Is there anything that should never have been saved (sensitive identification numbers,
      criminal history, immigration status)? Delete the file if so.

## 5. Confirm the fix took

- [ ] Start a new conversation and ask about the corrected fact.
- [ ] If the work continues in Cowork, confirm there too — it reads the same store.

## Whole-store options

- **Pause** memory for work that should not shape later conversations.
- **Reset** memory when the accumulated context no longer matches the situation. This clears
  what has been built up; decide deliberately.
