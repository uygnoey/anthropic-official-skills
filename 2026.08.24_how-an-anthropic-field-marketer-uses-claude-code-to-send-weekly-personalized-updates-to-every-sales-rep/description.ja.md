# Anthropic のフィールドマーケターが Claude Code で全営業担当者に週次パーソナライズ更新を届ける方法

## この記事について

Anthropic のフィールドマーケター Adam Ward が、日曜の夜に手作業で用意していたスライドを置き換え、担当する営業担当者ひとりひとりに月曜朝のパーソナライズされたダイジェストを自動生成する仕組みをどう作ったかを語る。最初の版はマーケティングのハッカソンで約 1 時間で組み上げ、その後数週間のパイロットのフィードバックで固めていった。

Ward の主張の中心は、マーケターに必要なのはコーディング能力ではなく、自分のビジネス課題を明確に説明する力だという点にある。彼は自身を技術者ではなくプロダクトマネージャーとして位置づけるプロンプトから始め、課題の説明を音声で録音して Claude にビジネス文脈を渡し、望む出力形式を示すテンプレート例を用意した。

## どんなときに役立つか

- 週次・月次など繰り返し送る更新を、手作業でパーソナライズするのに時間がかかっているとき
- 複数チームを支援していて、同じブリーフィングを相手ごとに切り直す必要があるとき
- CRM・イベント・コンテンツのデータが複数システムに散在し、担当者単位で突き合わせたいとき
- まず自己レビューのループとして始め、後から自律送信へ移行する展開経路が欲しいとき

## 主なポイント

- **ビジネス課題から話す。** 新しく入った同僚に引き継ぐようにClaude へブリーフする。Ward は自分を技術者ではなくプロダクトマネージャーとして位置づけ、課題の説明を音声で録音してビジネス文脈を伝えた。
- **望む形式を見せる。** 「今週の top three things」という構造で実行可能な項目を優先する出力テンプレート例が、抽象的な指示より効いた。
- **実データをつなぐ。** Claude を MCP 経由で BigQuery に接続した。BigQuery は HubSpot、Clay、Salesforce から取り込む Anthropic のマーケティングデータソースである。パーソナライズは CRM 上の担当テリトリー、Slack の関連アカウント更新、そしてマーケティング施策との突き合わせから生まれる。
- **すべての指摘を明示的なルールに変える。** 最初の 1 週間を終えた時点で、プロンプトにはそれぞれ特定のフィードバックに紐づく 9 つの明示的なコンテンツルールが入っていた。URL を決して捏造せず、正確なソースデータにあるリンクだけを描画すること。コンタクトの役職をイベントの想定参加者と照合して検証すること。業種ゲートを設けて小売アカウントに金融中心のイベントを出さないこと。担当アカウントがまだない新任セラーには専用のウェルカムメモを書くこと、などである。
- **スキーマ変動に耐えるプロンプトにする。** フィールドイベントのシートは 6 週間で 3 回、列の並びが変わった。解決策は、Claude にまずヘッダー行を読ませて列マッピングを検証させることだった。列位置をハードコードする代わりに、「イベント URL が入っている列を見る」といった意味ベースの指示を使う。
- **意欲のあるグループでパイロットする。** フィードバックを出すと約束した 10 名の営業チーム 1 つが、広い展開の前にデータ品質と関連性の不具合を洗い出してくれた。
- **スケールはコピーとフィールド 1 つの変更。** BDR が自分たち版を求めたとき、Ward はプロンプトを複製し、BDR が CRM 上でアカウントにどう紐づくかを表すフィールド 1 つだけを変えた。2 日でローンチした。続いてカスタマーサクセス、アライアンス、営業外のクロスファンクショナルなパートナー向けの版も生まれた。
- **測定できる効果。** ダイジェスト展開から 1 週間で、エグゼクティブディナーの登録者が倍になった。月曜の送信内容は監査と説明責任のために毎回アーカイブされ、マネージャーはチーム単位のロールアップを受け取り、Ward が休暇中もシステムは自走した。
