# Claude でコマースエージェントを作る

## この記事について

製品発表。Anthropic がコマースエージェントを作るためのオープンなブループリントを公開した。**ショッピング
エージェント** と **マーチャントエージェント** のリファレンス実装に加え、小売・旅行・通信・チケッ
ティングの例が含まれる。見出しの数字はこうだ。Claude 上でショッピングエージェントを運用する小売事業者
では、カートが最大 35% 大きくなり、購入完了の確率が 60% 高まった。

ショッピングエージェントはアプリケーションやウェブサイトに組み込まれ、カタログ検索、複数商品の
組み立て、好みの反映、商品比較、チェックアウトへ引き渡すためのカート構築、カスタマーサービスの質問を
扱う。マーチャントエージェントは売上パフォーマンスの質問に答え、在庫を追跡し、価格とプロモーションを
推奨し、キャンペーンを起草する。いずれも常に、人がデプロイ前に承認する提案としてだ。

Shopify、Priceline、Wix、Zomato、Fetch、Square がこの上で構築している例として挙げられ、Accenture、
Mastercard、Visa がパートナーとして参加している。

## どんなときに役立つか

- コマースエージェントのプロジェクトを始めるにあたり、空のリポジトリではなく動くリファレンスから
  始めたい。
- カタログ、カート、チェックアウト、好み、注文履歴のうち、エージェントが呼ぶ必要のある既存システムの
  範囲を見積もりたい。
- 買い手側と売り手側のどちらを先に作るか決めたい。
- デプロイ先を知りたい。Claude API、Amazon Bedrock、Microsoft Foundry、Google Cloud Vertex AI。

## 主なポイント

- **リファレンスエージェントが二つ、ブループリントが一つ。** ショッピング(消費者向け)とマーチャント
  (事業者向け)。
  [github.com/anthropics/commerce-agents](https://github.com/anthropics/commerce-agents) にある。
- **ショッピングエージェントの統合ポイント** はカタログ検索、カート管理、チェックアウト、顧客の好み、
  注文履歴。エージェントは既に運用しているシステムを呼び出す。
- **ショッピング用のガードレールが同梱される。** 価格と商品はカタログデータに限定され、操作的な
  アップセルのパターンは排除される。
- **マーチャント側の原則:** エージェントは変更を提案し、人がデプロイ前に承認する。
- **Claude が動く場所ならどこへでもデプロイできる** — Claude API、Amazon Bedrock、Microsoft
  Foundry、Google Cloud Vertex AI。
- **セットアップは速いと報告されている。** Wix のエンジニアは 15 分で動くコマースエージェントを得た。
  Fetch は両エージェントを 1 時間以内にローカルで動かし、ライブの会話が初回から動いた。
- **信頼が明示された制約である。** 決済パートナーの二社とも同じ枠組みで語る — Visa: *「AI はコマースを
  根本から作り変えるだろう。しかし信頼はあらゆる取引の中心にとどまらなければならない。」*
- **エンジニアリングの詳細は別記事。** アーキテクチャ、レイテンシー、キャッシュ、メモリ、安全性、eval
  は対になる詳説 *効果的なコマースエージェントの解剖学ガイド* にある。
