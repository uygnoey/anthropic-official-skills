# Chrome でのブラウザ操作の展開

## 何がリリースされたか

Claude in Chrome が、すべての有料 Claude プランで一般提供（GA）となった。安全性の検証に裏打ちされた
自律的なブラウザ操作を伴う。

## 何のための機能か

ブラウザ操作の要点はリーチである。ネイティブ統合が存在しないツール——誰もコネクタを作っていない社内
ダッシュボード、レガシーシステム、ベンダーポータルなど——に届くことだ。ブラウザ内で Claude は次の
ことができる。

- ウェブページを閲覧して操作する——テキストを読む、リンクをクリックする、ページ遷移する、フォームに
  入力する。
- デスクトップ・モバイル・ウェブのアプリで会話を続けながら、複数のブラウザタブをまたいで作業する。
- ブラウザにすでにあるログインを使って認証する。

すでにネイティブ統合があるシステムなら、そちらを使うべきだ。ブラウザ操作は、統合がカバーしていない
領域に対する答えである。

## 自律的なアクション

Claude は安全なアクションを自動的に承認するようになった。Claude Code の auto mode と同じ仕組みだ。
ユーザーはこの挙動を上書きできる。

したがって計画時の問いが変わる。「すべてのステップで止まって確認するのか」ではなく、「このタスクの
どのステップは人が先に見るべきか」だ。送信、提出、購入、公開、アカウント設定の変更は、何が自動承認
されるかに関わらずその範囲に入る。

## プロンプトインジェクションと 3 つの防御

悪意ある行為者は、ウェブコンテンツ——ウェブページ、メール、フォームフィールド——に指示を隠し、AI
エージェントの向きを変えようとする。これに対して 3 層の保護が展開されている。

1. **強化されたモデル学習。** 拡大し続ける攻撃ライブラリに対して学習する。ライブラリは社内の自動化
   ツール、外部のレッドチーム、実環境のモニタリングから供給される。
2. **プローブによるスクリーニング。** Claude が行動する *前* にウェブコンテンツを検査し、潜在的な
   攻撃の存在をモデルに警告する。
3. **アクション検証分類器。** 実行しようとしているアクションが、ユーザーの要求と一致しているかを
   確認する。

### 評価結果

より強力なレッドチーム攻撃でのテスト結果：

| 条件 | 攻撃成功率 |
| --- | --- |
| Claude Opus 5、セーフガード適用前 | 3.8% |
| プローブと安全分類器あり — Sonnet 5 | 0% |
| プローブと安全分類器あり — Opus 5 | 0% |
| プローブと安全分類器あり — Fable 5 | 0.3% |

これは率であって保証ではない。運用上の原則は変わらない。ブラウザが見せるものはデータであり、指示では
ない。

## 使い始める

- **個人ユーザー：** Chrome ウェブストアから Claude in Chrome をインストールする。
- **エンタープライズ管理者：** Organization Settings で管理する。ドメイン制限もここで設定できる。

ドメインリストの範囲を決めることが、展開時の主要な統制手段である。チームが実際に必要とするシステム
から始め、そこから広げていく。
