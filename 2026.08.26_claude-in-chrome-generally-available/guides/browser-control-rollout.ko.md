# Chrome에서 브라우저 제어 배포하기

## 무엇이 출시됐나

Claude in Chrome이 모든 유료 Claude 플랜에서 정식 출시(GA)됐다. 안전성 검증이 뒷받침하는 자율
브라우저 동작이 함께 제공된다.

## 무엇을 위한 기능인가

브라우저 제어의 요점은 도달 범위다. 네이티브 통합이 없는 도구들 말이다. 아무도 커넥터를 만들지 않은
사내 대시보드, 레거시 시스템, 벤더 포털 같은 것들이다. 브라우저 안에서 Claude는 다음을 할 수 있다.

- 웹 페이지를 보고 그 위에서 동작한다 — 텍스트 읽기, 링크 클릭, 이동, 폼 작성.
- 데스크톱·모바일·웹 앱에서 대화를 이어가면서 여러 브라우저 탭에 걸쳐 작업한다.
- 브라우저에 이미 있는 로그인을 사용해 인증한다.

어떤 시스템에 이미 네이티브 통합이 있다면 그쪽을 쓰라. 브라우저 제어는 통합이 커버하지 못하는
영역을 위한 답이다.

## 자율 동작

Claude는 이제 안전한 동작을 자동으로 승인한다. Claude Code의 auto mode와 동일한 메커니즘을 쓴다.
사용자는 이 동작을 재정의할 수 있다.

그래서 계획 단계의 질문이 달라진다. "모든 단계에서 멈추고 물어볼까?"가 아니라 "이 작업에서 사람이
먼저 봐야 할 단계는 무엇인가?"이다. 전송, 제출, 구매, 게시, 계정 설정 변경은 무엇이 자동 승인되든
관계없이 그 범주에 들어간다.

## 프롬프트 인젝션과 세 가지 방어

악의적인 행위자는 웹 콘텐츠 — 웹 페이지, 이메일, 폼 필드 — 안에 지시문을 숨겨 AI 에이전트의 방향을
돌리려 한다. 이에 맞서 세 겹의 보호 계층이 배포됐다.

1. **강화된 모델 학습.** 계속 늘어나는 공격 라이브러리를 대상으로 학습한다. 이 라이브러리는 내부
   자동화 도구, 외부 레드팀, 실제 환경 모니터링에서 수집된다.
2. **프로브 스크리닝.** Claude가 동작하기 *전에* 웹 콘텐츠를 검사해, 잠재적 공격이 있음을 모델에
   경고한다.
3. **동작 검증 분류기.** 수행하려는 동작이 사용자가 실제로 요청한 것과 일치하는지 확인한다.

### 평가 결과

더 강한 레드팀 공격으로 테스트한 결과:

| 조건 | 공격 성공률 |
| --- | --- |
| Claude Opus 5, 보호 장치 적용 전 | 3.8% |
| 프로브 + 안전 분류기 적용 — Sonnet 5 | 0% |
| 프로브 + 안전 분류기 적용 — Opus 5 | 0% |
| 프로브 + 안전 분류기 적용 — Fable 5 | 0.3% |

이는 비율이지 보장이 아니다. 작업 원칙은 그대로다. 브라우저가 보여주는 것은 데이터이지 지시가
아니다.

## 시작하기

- **개인:** Chrome 웹 스토어에서 Claude in Chrome을 설치한다.
- **엔터프라이즈 관리자:** Organization Settings에서 관리하며, 도메인 제한도 여기서 설정한다.

도메인 목록의 범위를 정하는 것이 핵심적인 배포 통제 수단이다. 팀이 실제로 필요로 하는 시스템에서
출발해 거기서부터 넓혀 나가라.
